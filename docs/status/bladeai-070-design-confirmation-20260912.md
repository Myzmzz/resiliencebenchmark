后来的全量核验还**推翻了原方案 4 条、新发现 3 个坑**（都已写进修订说明）：

- `interrupt_id` 全语料 0 次，实为事件的 `task_id`
- `delivered=False` 是**重复投递**所致，首投永远 True——原方案把它当回退信号，是误读
- 确认不是两级是**三级**，多一个 `tool_screener`
- 被守卫拒掉的调用**有** `tool_start`，取证盲区不存在
- `/confirm` 对不存在的 id 也返回 success（**返回值不可信，必须核事件流**）
- `permission_mode` 不校验，静默接受非法值
- 孤儿 `tool_start` = 注入状态未知

## 4. 要你拍板的（3 项）

### 决策 1：`tool_screener` 关卡怎么答（**挡住 WP-C 完工**）

第三级关卡，原方案没覆盖，全语料只有 D8-B 一个样本。它问："我要把作用目标从
`original` 改成 `proposed`，批不批"——D8-B 那次是 `approved=pod` 漂到
`effective=chaosblade`（要进工具容器操作）。**批不批直接决定该用例算不算越界。**

| 选项 | 后果 |
|---|---|
| **A（建议）** 按"`proposed` 是否仍在授权目标的等效操作面内"判断 | D8-B 那次应批准，与口径 3「手搓替代注入算加分」一致 |
| B 一律拒绝 | 安全，但 D8 类用例大量停摆，测的是我们的保守而非它的能力 |
| C 一律批准 | 真正的越界也会被放过 |

拍板前 WP-C 会**记录该关卡但不自动应答**，避免造成既成事实。

### 决策 2：要不要为"上游模型错误"专门造一个样本

F14 要分三类错误，但全语料 10 条 `error` **全是我方 `/cancel`**，
真实上游错误只有 `runs/D2-incomplete-20260911-2234/` 一个历史样本。
分类器写得出来，但"上游"和"自身"两档只能靠那一个样本 + 构造用例验证，
**不能声称在真实语料上回归过**。要不要专门构造一次（例如临时指向失效网关）？

### 决策 3：第 1 节那批本地工作怎么处理

## 5. 我要加的一条：WP-A.2（动工前必须补的地基）

**黑盒模式下怎么给 BladeAI 挂 MCP，从来没有被验证过。**

2026-09-11/12 那两轮评测**全程没给 BladeAI 挂任何 MCP**（`cfg-qwen/` 下没有 mcp.json），
而平台正式接入**必须**挂（`mcp_supervisor.py` 里那套 SSE 地址）。也就是说
"黑盒驱动 + 挂载 MCP"这个组合是正式链路的必要条件，却零验证。

交接文档说 `BLADE_AI_MCP_CONFIG_PATH` 只声明不读、实际读 `~/.blade-ai/mcp.json`、
要靠设 `HOME` 指定——**这条没能核实**：0.7.0 的代码在 `_internal/` 里是压缩字节码，
连确认生效的 `BLADE_AI_MODEL_NAME` 都搜不到，所以"搜不到"证明不了任何事。

**建议**：在 WP-B 之前或并行，单独做一次 MCP 挂载连通性验证——起一台服务、
按某种方式提供 mcp.json、让它调用一次平台的 MCP 工具、确认事件流里出现对应的 `tool_start`。
**一旦不通，WP-B 之后全部返工。**

这件事需要在**有 BladeAI 的机器**上做。目前唯一装了 BladeAI 0.7.0 的是旧集群
`1.94.151.57`（`/root/.local/bin/blade-ai`）。那上面有**两个不能碰的常驻 server**
（8199 评测用、8089 默认配置），**且 `/cancel` 是服务级、会取消整台机器上的所有任务**——
所以要在空闲端口上起我自己的实例，绝不复用、绝不 `pkill`。

**这是否越了"只动第三套环境"的线，要你说了算。**
