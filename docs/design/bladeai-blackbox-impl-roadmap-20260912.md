## 三、未核验的已知风险

诚实列出我**没能核实**的，不要当成已解决：

### 风险 1：黑盒模式下怎么给 BladeAI 挂 MCP（**方案完全没覆盖**）

交接文档 §2.1 称 `BLADE_AI_MCP_CONFIG_PATH` 只声明没代码读、实际读
`~/.blade-ai/mcp.json`、要靠设 `HOME` 指定。**这条我没能核实**：
0.7.0 的代码在 `_internal/` 里是压缩字节码，字符串搜索无效
（连确认生效的 `BLADE_AI_MODEL_NAME` 都搜不到），所以"搜不到"证明不了任何事。

**为什么这是风险**：2026-09-11/12 那两轮评测**全程没有给 BladeAI 挂任何 MCP**
（`cfg-qwen/` 下没有 mcp.json），而平台正式接入是要挂 MCP 网关的
（`mcp_supervisor.py` 里那套 SSE 地址）。也就是说
**"黑盒模式 + 挂载 MCP"这个组合从来没有被验证过**，而它是正式链路的必要条件。

**建议**：在 WP-B 之前或并行，单独做一次**MCP 挂载连通性验证**——
起一台服务、按某种方式提供 mcp.json、让它调用一次平台的 MCP 工具、确认事件流里
出现对应的 `tool_start`。这件事原方案里没有工作包，**建议新增为 WP-A.2**，
因为它和传输层一样属于"地基"，且一旦不通会让 WP-B 之后全部返工。

### 风险 2：`result` 事件结构只看了一个样本

WP-B 要把 `result` 映射成 `Checkpoint` + 终态。我只详查了 L0 的那一条
（`content` 是 JSON 字符串，含 `task_id` / `experiment_uid` / `fault_handle` /
`recovery_handle` / `fault_spec` / `injection_method` 等）。
拒绝类用例（L4/P2）和扰动类（D1）的 `result` 结构是否一致，**未逐个核**。
WP-B 开工第一件事应该是把 17 个用例的 `result` 全 dump 出来对结构。

### 风险 3：本轮全部结论只覆盖 qwen3.8-max 一个模型

语料和联调都是 qwen3.8-max。`done` 前用普通文本提问（F10）这类行为是**模型行为**，
换模型后频率可能变化；但关卡机制、事件字段、端点契约属于**产品结构**，不随模型变。
把两者分开看：结构性结论可以信，行为频率性结论（例如"11/17 个用例有无关卡回合"）
换模型要重测。
