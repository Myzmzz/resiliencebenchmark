# RD-09 风险：关键和非关键功能共享可耗尽资源；后果：非关键功能耗尽资源并拖垮关键功能

本模板使用`network-delay`或`cpu-load`中的一个原子故障，用于证明一条非关键/故障路径会通过同一可耗尽资源对象拖垮另一条关键路径。共用Pod、进程或语言Runtime不等于已证明共享资源。

首先用CodeGraph分别定位至少两条可达入口，其中至少一条具有可证明的关键性契约。追踪两条路径到Executor、Connection Pool、Queue、Semaphore、Worker Group或可配额CPU时间，必须证明它们引用同一对象或同一配置实例。然后核对容量、预留、分区配额、优先级和拒绝策略。

主动查找反证：独立池/执行器、硬分区配额、关键路径预留容量、优先级或有效拒绝，以及能在耗尽前释放资源的超时/取消。注入要优先作用于非关键依赖，并独立观察两条路径和共享资源占用。

单路径准入/无界队列属于RD-03；只有Deadline/取消错误属于RD-01。候选必须形成“两条路径→同一资源对象→非关键路径占满→关键路径饿饿”的证据链。Oracle必须分路径展示SLO，并记录共享池/队列/配额的状态与恢复。
