# RD-08 风险：实例恢复流程过早就绪或无法收敛；后果：Pod显示正常但业务迟迟不能恢复

本模板使用`pod-delete`或`pod-fail`中的一个最小原子故障，专门调查替换/重启实例从启动到真正恢复业务能力的收敛过程。它不调查稳态Probe语义，也不因单副本就输出候选。

用CodeGraph定位启动初始化、状态加载、连接重建、缓存预热、注册、领导者选举、重试和Readiness转换的真实路径。核对重试上限、退避抖动、StartupProbe/Readiness阈值、滚动发布和Service Endpoint。“Pod Ready”只是中间状态，必须继续查到首次成功业务以及一个稳定观察窗口。

主动查找反证：Readiness只在所有必需初始化完成后成功；重试有硬上限、指数退避和抖动；恢复流量逐步重进入；多实例不会同步冲击依赖。候选必须能由新UID时间线、Ready振荡、重试/连接风暴和业务SLO证明。

稳态Health误分类属于RD-06；纯副本容量清空属于RD-05；状态丢失或错误重放属于RD-10。`available_fault_types`只能从`pod-delete`和`pod-fail`中选一个，恢复完成必须以真实流量与稳定SLO证明。
