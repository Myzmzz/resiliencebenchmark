# RD-10 风险：状态写入、确认和重放缺少一致性保护；后果：服务重启后数据丢失、重复或状态不完整

本模板使用`pod-delete`或`memory-load`中的一个最小原子故障，专门检查状态转换被中断/重启后的持久化、原子性、幂等性与重放安全。无状态业务路径不适用此模板。

从真实业务入口追踪到事务提交、数据写入、消息确认、检查点、本地状态和外部副作用。用CodeGraph核对顺序与异常路径，查找幂等键、去重、WAL、Outbox/Inbox、重放、补偿和对账机制；同时关联PVC、外部存储与可注入Pod。

主动查找反证：原子事务；WAL/Outbox保证；持久幂等键与服务端去重；确认与副作用的安全顺序；可自动重建的检查点；独立状态对账和补偿。注入时必须对齐到已证明的状态转换窗口，否则只是无效中断。

远程丢包引起的未知响应/重试属于RD-02；纯副本容量丢失属于RD-05；无持久状态的在途请求终止属于RD-07。Oracle必须通过业务实体的唯一性、完整性、顺序性、余额/数量对账和重放结果判定，不得用Pod重启成功代替。
